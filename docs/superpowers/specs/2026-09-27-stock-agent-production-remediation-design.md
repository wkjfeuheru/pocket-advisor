# stock_agent 生产链路修复设计

## 目标

修复既有 `stock_agent` 的生产接线、数据正确性、风险控制和可恢复交互问题，使三个既定场景在不改变项目目录结构、不修改或依赖 `FAVersion2` 的前提下，遵守 `2026-09-27-stock-agent-three-scenarios-design.md` 的契约。

本修复不扩展新的股票业务场景，也不改变主 LangGraph 的四 Agent 结构。

## 修复边界与顺序

按生产可用性优先级实施：

1. 持久化快照与生产仓库接线。
2. Fuyao MCP 目录、标准化适配和实体解析。
3. 深研、市场总览、筛选的正确性与降级语义。
4. 评分、证据、澄清、输出安全与最终解释。
5. 后端、前端和真实只读契约验证。

每项先新增能复现问题的测试，确认失败后才修改生产代码。

## 数据与持久化

### StockFeatureStore

保留 `MemoryStockFeatureStore` 仅作为单元测试替身。新增与现有 `finance.stock_feature_snapshots`、`finance.stock_features` 对应的 PostgreSQL 仓库，实现与内存仓库相同的接口：

- `begin_snapshot`、`add_features`、`publish_snapshot`、`fail_snapshot`；
- `latest_ready`、`universe_rows`；
- 发布在一个数据库事务内完成，并清理超过 30 个的成功快照；
- 只查询 `ready` 快照；三日内附加过期警告，超过三日抛出 `stock_snapshot_stale`。

运行时和 `scripts.refresh_stock_features` 均通过同一工厂取得 PostgreSQL 仓库。刷新命令注入可替换数据源，生产默认数据源必须返回真实、可追溯的因子数据；没有数据时标记失败而非发布空快照。

## Fuyao 适配与实体解析

MCP 工具不直接泄露给模型。`FuyaoClient` 保留内部业务操作名，但新增明确的“真实工具名 + 参数 + 响应 DTO”映射层：

- 元数据目录负责股票、指数、行业和指数成分校验；
- 行情、K 线、财务、估值和市场统计均转换为内部统一字段，并带 `source`、`as_of`；
- 适配层只允许读操作，未知工具、未知字段和上游业务错误转为受控信封；
- 版本约束和启动冒烟测试保证 `mcp` 与 `langchain-mcp-adapters` 可实际加载。

`resolve_entities` 改为异步节点：每次请求通过目录解析股票、指数、行业；零命中或歧义只返回服务器候选，不进入业务节点。`index_scope` 必须取到有效成分表，否则返回受控失败，绝不退化为全市场。

## 三个场景

### 市场总览

固定七个指数、市场广度、成交额、涨跌停/连板、行业和概念前后五名均由 Fuyao 标准 DTO 提供。交易日历决定盘中或收盘新鲜度：盘中超过五分钟的报价不可用，收盘后允许最近交易日收盘数据。实时行情整体失效时整个总览失败，不能补写数值。

### 个股深研

对最多三只股票使用有界并发：每只股票的行情、财务、K 线、公司资料与 Tushare 事件并行获取，股票之间也并行；同步 Tushare SDK 调用统一放入线程池。单只失败保留其他标的；只有所有标的缺少关键证据时才失败。

新闻请求应用 30 日窗口和标的关联过滤，不再把任意全市场新闻硬塞给请求股票。结构化业绩预告、解禁、质押、股东变动分别获取、转换为只含标题、来源、链接、时间、关联标的、标签和置信度的公开事件。

### 研究候选池

筛选严格应用行业和指数成分范围，再执行硬过滤。策略关键因子只要缺一项即剔除，不把缺失值当作零值。评分以行业横截面进行 5%/95% 缩尾和分位转换；`short`、`medium`、`long` 分别选择已写明的周期因子，长周期额外提高稳定性权重。候选只来自可用快照，不读取或展示实时价格。

## 安全、证据和解释

使用版本化、字段白名单的公开 DTO 传递 artifact 与 `public_metadata`，不再对任意嵌套字典做浅层删字段。每个公开数字在叶子或所属指标组上必须可追溯到 `source` 与 `as_of`；无法证明来源的字段删除。

澄清选项改为按字段声明：`strategy` 与 `horizon` 分别拥有允许值；服务端仅接受声明字段及其对应选项。恢复后再次验证规范化请求。

股票结果的受控摘要和结构化证据摘要将进入主图 `aggregator` 的材料。最终 `output_guard` 在所有回答（包括 aggregator 输出）上拒绝买卖指令、买卖点、目标价和仓位比例；保留“模拟交易、非投资建议”声明。

## 验证

新增失败回归测试覆盖：

- CLI 刷新与运行时跨进程读取同一 PostgreSQL 快照；空刷新不得发布；
- Fuyao 工具目录、参数、响应 DTO 和启动加载；
- 股票/指数/行业解析、无效指数范围拒绝；
- 三个周期的行业分位、关键缺失过滤、固定黄金样本；
- Tushare 日期和标的过滤、结构化事件、非阻塞调用；
- 全部证据缺失时深研失败、单标的失败时部分成功；
- 按字段澄清校验、最终文本禁令、artifact 深层字段白名单；
- aggregator 能依据股票摘要解释，而不泄露原始响应；
- 前端澄清控件按字段显示合法选项，市场板块与风险信息可展示。

完成后运行后端全量 `pytest -q`、前端测试、前端构建，以及不输出凭据的 Fuyao 只读启动/目录冒烟测试。

## 验收标准

- 刷新脚本发布的快照可由另一个 Web 进程读取；
- 真实 A 股、指数、行业都能由 Fuyao 目录解析或安全澄清；
- 选股严格遵守范围、因子、周期与快照新鲜度；
- 三场景上游局部故障按原设计降级，且不编造数据；
- SSE、历史记录和最终回答只含可公开、可追溯的结果；
- `FAVersion2` 保持不变且没有生产导入。
