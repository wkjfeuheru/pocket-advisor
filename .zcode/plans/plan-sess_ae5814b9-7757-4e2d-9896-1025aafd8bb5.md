在 Supervisor 主图最前端新增 query-rewrite 节点，显式实现多轮追问理解与指代消解

## 设计

新节点 `resolve_query`（query-rewrite），位于 `START → resolve_query → classify_intent`，取代原 `START → classify_intent`：

1. **触发条件**（首轮零开销）：检查 `messages` 中在本轮输入里的用户消息条数。会话此前没有历史（当前消息即第一条用户消息）时，直接原样放行，不调用 LLM。现有测试全部是单消息输入，行为不变。
2. **改写逻辑**：有历史时，用 `model.with_structured_output(RewrittenQuery, method="function_calling")` 调用一次 LLM，输入 = 系统提示（要求：结合上文把最新的用户消息改写成自包含的问题，解析"它/那只基金/上面提到的"等指代；无法确定时保持原文；不回答问题，只输出改写结果）+ 近 N 条历史 + 本轮最新用户消息。输出结构：`RewrittenQuery { task: str, changed: bool }`。
3. **降级**：改写 LLM 调用抛异常且 `is_degradable(exc)` 时，记一条 warning（"问题理解暂不可用，按原样处理"）并放行原始消息；不可降级异常照常上抛。
4. **状态流**：不改写 `messages`（避免污染持久化历史），把改写结果写入新状态字段 `resolved_task: str`。下游 `classify_intent` 的用户 prompt 侧材料改为优先使用 `state["resolved_task"]`（无则回落最后一条用户消息）；`dispatch_intents` 的 `Send` 载荷同样带上 `resolved_task`，`_task_for` 优先读取它。

## 改动文件

1. `app/agents/graphs/state.py`
   - 新增 `RewrittenQuery(BaseModel)`（`task: str`、`changed: bool = False`）并导出
   - `AdvisorState` 增加 `resolved_task: str`
2. `app/agents/prompts/task_agent_prompts.py`
   - 新增 `RESOLVE_SYSTEM_PROMPT`（指代消解规则，风格对齐现有 CLASSIFY 提示词）
3. `app/agents/graphs/task_agent.py`
   - 新增 `resolve_query` 节点 + 注册 `graph.add_node` / 边 `START → resolve_query → classify_intent`
   - `STAGE_LABELS` 增加 `"resolve_query": "理解追问"`
   - `classify_intent` 与 `dispatch_intents`/`_task_for` 优先使用 `resolved_task`
4. `tests/test_agents/test_advisor_graph.py`
   - `ScriptedModel` 增加 rewrite 通道：`with_structured_output` 按 schema 分流（`RewrittenQuery` 返回预设改写值），记录 rewrite 输入供断言
   - 新增测试：a) 多轮"那它呢"被改写并路由到正确 agent；b) 单条消息不触发 rewrite（不产生第二次 structured 调用）；c) rewrite 失败降级为原消息并带 warning

## 不改动

- `agent_service.py`：新节点自动纳入 `STAGE_LABELS` → SSE `status` 事件与落库，`durability="sync"` 对新节点同样生效，无需改动
- 前端：`state.ts` 直接展示后端下发的 stage 字符串，无需改动
- `test_portfolio_allocation_graph.py` / `test_stock_smoke.py`：复用 `ScriptedModel`，单消息输入走首轮跳过路径，`with_structured_output` 分流后对 `IntentResult` 调用无影响
